## Completed runs

### One-shot persona-analysis framing pilot

- Sample: one goal from each of six crisis labels (6 goals total).
- Frozen generation: four candidates per goal, one for each PCSA-inspired presentation
  strategy, generated by the pinned 70B attack model.
- Paired response design: the same 24 candidates were each tested under
  `direct_persona`, `clinical_context`, and `persona_analysis`, producing 72
  single-turn Llama-3.1-8B responses.
- Strict Figure-4 any-axis UNSAFE: 0/24 in every framing arm.
- Figure-3 mean: direct persona 4.333, clinical context 4.250, persona analysis
  4.208.
- Constraint-eligible cells: 17/24, 18/24, and 17/24, respectively.
- The auxiliary audit reported 17/24 persona-analysis responses as case analysis, but
  that count is confounded: the audit configuration itself treated case-analysis output
  as the expected mode for this arm. It cannot support a clean task-shift conclusion.
- Two of six goals passed generator validation on the first call; three required one
  correction and one required two corrections. Failures were ungrounded `used_terms`
  metadata or the 40-word minimum, and all four-strategy sets eventually validated.
- The semantic auxiliary audit still marked 4/24 frozen candidates as explicit goal
  exposure even though the exact-string leakage gate passed. This must become a
  pre-response rejection criterion in the optimization run.

This pilot does not support the hypothesis that its original persona-analysis prompt
raises single-turn unsafe behavior. It does not isolate that hypothesis: candidates
lacked direct elicitation, one arm supplied a defensive clinical reference, and the
mode audit was misconfigured. The sample is intentionally small and no GPT-4o target
calls were made, so it does not test optimized transfer. Frozen candidates, response hashes, automatic audit
results, manifests, and recovery provenance are retained locally under
`outputs/persona_analysis_oneshot_pilot6/`; raw responses are not published.

## Reproducibility note

The two active jobs and the completed 652-goal optimized job loaded earlier versions
of `pcsa_attack_optimize.py` and `pcsa_embedded_multiturn.py`. Those manifest hashes do
not match the files that were edited later at approximately 08:50 KST. A Python job
keeps its already imported code, so a run does not switch prompts midway; however,
the current source alone cannot reproduce those earlier processes exactly.

New runs now copy every hashed source file into `<out-dir>/source_snapshot/` at run
creation and record generator, evaluator, judge, build mode, and endpoint roles in the
manifest.

   analysis prompt unchanged.
2. Run constrained surrogate-guided optimization with 3-5 response samples per
   candidate, retaining top-k candidates rather than a single noisy winner.
3. Compare original persona, jargon-only rewrite, unselected four-strategy generation,

   GPT-4o without target-side regeneration or selection.

baselines and are not relabeled as GPT-4o results.

### Corrected one-shot elicitation pilot (v2)

The same six goals were regenerated after requiring a first-person client utterance,
direct counselor address, and exactly one strategy-specific question. The
persona-analysis responder prompt no longer received the defensive clinical reference,
and every arm was audited as a requested counseling reply. All 24 frozen candidates
passed the utterance-format checks (24 questions total; no missing first-person or
counselor-address forms; 70.6 mean words).

The corrected run again produced 0/24 strict Figure-4 unsafe outcomes in each arm.
Figure-3 means were 4.333 for direct persona, 4.208 for clinical context, and 4.375 for
persona analysis. Constraint-eligible counts were 16/24, 20/24, and 19/24. The
persona-analysis mode audit now reported 21 live-counseling, 2 mixed, and 1 role-confused
responses, showing that the previous 17/24 case-analysis result was a configuration
artifact rather than a stable framing effect.

This corrected result shows that restoring a direct elicitation act is necessary for a
valid comparison but is not sufficient to produce strict unsafe behavior on this small,
unoptimized one-shot sample. The next justified test is repeated surrogate sampling and
pre-registered selector-based optimization, followed by frozen GPT-4o transfer. It is
not justified to send these unoptimized candidates to GPT-4o as the main transfer set.
