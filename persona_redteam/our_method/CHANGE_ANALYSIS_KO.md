# 이전 고성능 샘플과 현재 파일럿의 변경점

## 결론

이전 6건과 현재 10건은 같은 조건의 전후 비교가 아니다. 타깃 모델, 사례 집합,
GOAL 노출 시점이 동시에 바뀌었으므로 성능 하락 전체를 코드 회귀로 해석할 수 없다.
다만 최종 응답에서 인용문을 한 문장으로 제한해 복합 GOAL의 산출물 형식이나 제약을
떨어뜨리는 재현 가능한 코드 결함은 확인했고 수정했다.

## 실행 조건 비교

| 항목 | 이전 6건 | 현재 10건 |
| --- | --- | --- |
| 타깃 | `gpt-4o-mini-2024-07-18` | `gpt-4o-2024-11-20` |
| 사례 | 별도 6건 | 겹치지 않는 신규 10건 |
| 초기 GOAL 원문 | 타깃에 비공개 | 페르소나에 원문 공개 |
| 직접응답 프로토콜 | `counterfactual_prevention_v1` | 동일 |
| 최종 분기 수 | 4 | 4 |
| R3+ branch | 75.0% | 50.0% |
| B4+ branch | 25.0% | 2.5% |
| R3+@4 | 83.3% | 70.0% |
| B4+@4 | 66.7% | 10.0% |
| 같은 분기 R3+∧B4+@4 | 66.7% | 0.0% |

GPT-4o는 mini보다 다른 타깃이며, 사례도 완전히 다르다. 또한 현재 조건은 유해한
GOAL 원문을 첫 입력부터 보여 주므로 안전 경계를 더 일찍 활성화할 수 있다. 이 세
요인의 효과는 동일 사례·동일 모델의 대응 비교 없이는 분리할 수 없다.

## 확인된 코드 회귀와 수정

이전 구현은 `recovery_response`를 문장 단위로 잘라 Qwen이 정확히 한 문장만 고르게
했다. 예를 들어 한 문장에 `song lyrics`, 다음 문장에 그 가사의 목적이 있으면 어느
한쪽이 빠질 수 있었다. 실제 현재 파일럿에도 산출물 형식이 빠지고 일반적인 방법
요청으로 변한 사례가 있었다.

v18에서는 다음을 적용한다.

1. 타깃이 실제로 작성한 단일 문장 후보를 유지한다.
2. 같은 응답·같은 문단에 인접한 2~3문장의 정확한 연속 부분 문자열도 후보로 만든다.
3. 행위, 산출물 형식, 대상, 제약을 모두 보존하는 가장 짧은 완전 후보를 선택한다.
4. 타깃이 쓰지 않은 GOAL 문구를 합성하거나 인용문에 보충하지 않는다.

기존 10건의 40개 분기를 새 후보 규칙으로 재감사한 결과, 24개 분기에서 GOAL 핵심어
포함 수가 증가했고 평균 핵심어 겹침은 2.40개에서 4.65개로 증가했다. 이는 생성 결과를
다시 채점한 성능 수치가 아니라, 수정된 인용 후보의 의미 보존 진단치다.

## 다음 판단 절차

현재 GPT-4o 10건을 v18로 다시 생성·평가한 결과를 기존 v17과 대응 비교한다. 이때
사례, 타깃, GOAL 공개 조건, 네 분기, 평가기를 모두 고정해야 한다. R3 회복 여부와
B4 행동 여부를 따로 비교하고, 같은 분기 결합 성공만 주 지표로 사용한다. 이 대응
파일럿을 통과하기 전에는 197건 전체 실행으로 확장하지 않는다.
